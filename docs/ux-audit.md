# SmsSink 体验走查（UX Audit）

> 走查对象：托盘区图标与右键菜单、通知卡片、系统 Toast、管理台入口与交互反馈。
> 判定标准：不是"能不能用"，而是"第一次用的人会不会看不懂、会不会在心里骂一句"。
> 严重度：**P0 = 数据/信任受损或功能实为失效**；**P1 = 明显摩擦或认知负担**；**P2 = 打磨项**；**P3 = 锦上添花**。
> 状态：`已修` 表示本次已改代码并验证；`待办` 表示已给方案、进 backlog。

---

## 0. 一句话结论

这个产品的核心链路（收 → 提 → 通知 → 复制）是通的，但**它有三个"沉默"**：
出了错沉默、做了事沉默、没看见也沉默。用户体验上的廉价感几乎全部来自这里，而不是视觉。
视觉层面此前已修掉字体与 DPI 两个硬伤；本轮把"沉默"补上，并把托盘菜单从"五个平铺入口"改造成"状态 + 最近验证码 + 设置"的信息架构。

## 7. 第二轮走查：视觉细节（依据实机截图）

第一轮把「沉默」补上之后，用户贴着实机截图指出了六处排印与手感问题。
这一轮全部与「信息在有限宽度里怎么排」有关，逐条改完并复验。

| # | 严重度 | 现象 | 影响 | 处理 | 状态 |
|---|---|---|---|---|---|
| VH-6 | P1 | 时间独占正文上方一行（`2026-11-11 16:47:43`），把卡片纵向切成一堆等宽横条 | 时间属于元信息，却占着和正文一样的位置，视线被反复打断 | 时间移到**标题行右侧**（`DT_RIGHT`），标题用剩余宽度并 `DT_END_ELLIPSIS` | 已修 |
| VH-7 | P1 | 原文只有一行，长短信在「您正在使用短…」处截断 | 关键词有一半在第二行，用户判断不了这条是不是自己要的 | 原文改两行（`DT_WORDBREAK`），卡片 180 → 192px 让出空间；超出两行才补省略号 | 已修 |
| VH-8 | P1 | 两个按钮宽度写死 72 / 60，`复制` 两个字居中后两侧各空 20+ px，而两键间距只有 8px | 「框比字大一圈」，两键又贴在一起，观感不协调 | 宽度按文案实测（`GetTextExtentPoint32W`）+ 两侧各 14px；间距 12px；状态文案变长时按钮向左长开、右边缘不动 | 已修 |
| FB-7 | P1 | 「复制」悬停 = 强调色压暗 8%，`#2563EB` → `#2255D8`，几乎不可辨 | 用户以为按钮没有悬停反馈 | 改为向卡片底色提亮 16%（`#2563EB` → `#477BEE`），深色主题下自然变成压暗 | 已修 |
| OE-5 | P1 | 悬停在按钮上时光标仍是箭头 | 少了「这里可以点」的最后一层暗示 | 子类化按钮窗口过程，`WM_SETCURSOR` 返回手型（`IDC_HAND`） | 已修 |
| FB-8 | P1 | 鼠标停在托盘图标上没有任何提示（`NOTIFYICON_VERSION_4` 下缺 `NIF_SHOWTIP`，Shell 不认 `szTip` 为标准 tooltip） | 用户没法确认图标属于哪个程序、是否在监听 | 补 `NIF_SHOWTIP`，提示文案改为「应用名 · 监听端口 · 今日 N 条 · 最后 HH:MM」 | 已修 |

附带修掉的一个实现坑：按钮一旦接住鼠标，`WM_MOUSEMOVE` 就不再冒泡到卡片，
第一轮只能靠 250ms 的进度节拍兜底采样，hover 会慢半拍。子类化之后
按钮自己上报 hover，并 `TrackMouseEvent(TME_LEAVE)` 及时清掉。
