# 管理台体验走查（UX Audit · 管理台）

> 走查对象：`assets/index.html`（最近记录 / 规则管理 / 统计 / 设置 四个页签）。
> 上一轮走的是托盘菜单与通知卡片，本轮只碰管理台，不改托盘与卡片。
> 严重度：**P0 = 信息丢失或功能实际不可用**；**P1 = 明显摩擦或认知负担**；**P2 = 打磨项**；**P3 = 锦上添花**。
> 状态：`已修` = 本轮改完并截图验证；`待办` = 已给方案，进 backlog。

---

## 0. 一句话结论

这个页面的问题不是"丑"，而是**没有刻度**：9 种字号、15 种内边距、8 种圆角、1 档阴影挂在 5 个层级上。
没有刻度，就没有主次，用户只能靠"读完全部"来理解页面——这才是"傻大粗笨"的实感来源。
本轮做的不是换配色，而是**把感觉翻译成有限的几档数值，并且只允许用这几档**。

## 补：列表页工具条回归修复 + 切页签刷新

**用户反馈**：其他页签切回「最近记录」时要刷新列表。

**排查发现的真实问题比反馈更重**：上一轮重写管理台时，列表页的四个绑定在替换脚本的
过程中整段丢失——「刷新」「上一页」「下一页」「导出 CSV」全部变成死按钮，筛选框回车
也不生效。所以用户实际感受到的是"这个列表只有切页签才会变"，切页签成了唯一可用的
刷新手段。上一轮的验证清单里写了"四个页签的数据加载与交互均可用"，但只测了点行展开
和复制按钮，没点过工具条——**验证覆盖不到的按钮，等于没有验证**。

### 改动

| 位置 | 改动 | 原因 |
|---|---|---|
| 页签切换 | `PANE_LOAD` 映射，切到哪页就拉哪页的数据 | 常驻程序一直在收短信，切回列表看到的应是当前数据而不是上次渲染的快照 |
| 筛选条件 | 切换页签不清空 | 用户设的来源/规则/关键词是意图，不该因为看了一眼前面的统计就丢 |
| 按钮绑定 | 恢复刷新 / 上一页 / 下一页 / 导出 CSV；筛选框回车即刷新 | 补回丢失的事件；改条件一律回第 1 页，避免停在越界的空白页 |
| 分页边界 | 请求 `limit=PAGE_SIZE+1`，多出的一条只用来判断还有没有下一页 | 后端不返回总数，靠"满页"推断会在最后一页之后留一个空页 |
| 按钮态 | `btnPrev` 在首页禁用、`btnNext` 在末页禁用 | 死按钮比灰按钮更让人困惑；`.btn[disabled]` 已有样式 |
| 首屏 | 删掉 `location.hash==='#recent'` 的补点 | `#recent` 本来就是默认页，这行会在启动时多拉一次列表 |

### 验证（只读 mock + 无头 Chrome，统计 `/api/messages` 命中次数）

| 步 | 操作 | 请求数 | 结果 |
|---|---|---|---|
| 1 | 打开页面 | 1 | 首屏只拉一次（删掉 hash 补点后不再翻倍） |
| 2 | 点「刷新」 | 2 | 按钮生效 |
| 3 | 切到规则 / 统计 | 2 | 别的页签不打扰列表 |
| 4 | 切回最近记录 | 3 | **刷新发生**；筛选框内容保留 |
| 5 | 原地再点「最近记录」 | 4 | 也可以当手动刷新用 |
| 6 | `PAGE_SIZE=5` 造多页 | — | 首页 next 可点 prev 禁用；第 3 页只剩 2 条时 next 自动禁用，无空页 |
| 7 | 点「导出 CSV」 | `/api/export.csv` +1 | toast「CSV 已导出」 |

（页签切换只有 3 个页面需要拉数据：规则页保持内存中的编辑态，切回来不重拉，
否则会丢掉未保存的改动。）
